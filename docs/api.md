# E-Commerce Microservices — API Documentation

## 1. Base URL

When running through Docker:

```text
http://localhost:8080
2. Authentication

Protected APIs require a JWT.

Send the token using:

Authorization: Bearer <JWT_TOKEN>

The JWT is generated by the User Service during login.

The API Gateway validates the JWT before forwarding protected requests.

3. Health Check
GET /health

Checks whether the API Gateway is running.

Authentication: No

Example:

curl http://localhost:8080/health

Response:

{
  "status": "ok"
}
4. User APIs
4.1 Register User
POST /api/v1/users/register

Creates a new user.

Authentication: No

Request:

{
  "name": "Sagar",
  "email": "sagar@example.com",
  "password": "password123"
}
4.2 Login
POST /api/v1/users/login

Authenticates a user and returns a JWT.

Authentication: No

Request:

{
  "email": "sagar@example.com",
  "password": "password123"
}

Response:

{
  "token": "<JWT_TOKEN>",
  "user": {
    "id": 1,
    "name": "Sagar",
    "email": "sagar@example.com"
  }
}
4.3 Get User
GET /api/v1/users/:id

Returns a user's information.

Authentication: Yes

Example:

curl \
  -H "Authorization: Bearer <JWT_TOKEN>" \
  http://localhost:8080/api/v1/users/1
4.4 Update User
PUT /api/v1/users/:id

Updates user information.

Authentication: Yes

Request:

{
  "name": "Sagar Acharya",
  "email": "sagar@example.com"
}
5. Product APIs

Product read operations are publicly accessible.

Product write operations require authentication.

5.1 List Products
GET /api/v1/products

Returns all products.

Authentication: No

Example:

curl http://localhost:8080/api/v1/products
5.2 Get Product
GET /api/v1/products/:id

Returns a product by ID.

Authentication: No

Example:

curl http://localhost:8080/api/v1/products/1
5.3 Create Product
POST /api/v1/products

Creates a product.

Authentication: Yes

Request:

{
  "name": "Laptop",
  "description": "Development laptop",
  "price": 75000,
  "stock": 10
}

Example:

curl \
  -X POST \
  -H "Authorization: Bearer <JWT_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Laptop",
    "description": "Development laptop",
    "price": 75000,
    "stock": 10
  }' \
  http://localhost:8080/api/v1/products
5.4 Update Product
PUT /api/v1/products/:id

Updates an existing product.

Authentication: Yes

Request:

{
  "name": "Updated Laptop",
  "description": "Updated description",
  "price": 80000,
  "stock": 15
}
5.5 Delete Product
DELETE /api/v1/products/:id

Deletes a product.

Authentication: Yes

Successful deletion returns:

204 No Content
6. Order APIs

All order APIs require authentication.

The authenticated user's identity is determined from the JWT.

Clients cannot choose the owner of an order by supplying a different user_id.

6.1 Create Order
POST /api/v1/orders

Creates an order for the authenticated user.

Authentication: Yes

Request:

{
  "user_id": 1,
  "product_id": 1,
  "quantity": 2
}

The user_id supplied by the client is not trusted.

The authenticated JWT user ID is used instead.

6.2 Get Order
GET /api/v1/orders/:id

Returns an order.

Authentication: Yes

A user can only access their own order.

If the order belongs to another user:

403 Forbidden

Example:

curl \
  -H "Authorization: Bearer <JWT_TOKEN>" \
  http://localhost:8080/api/v1/orders/1
6.3 Get User Orders
GET /api/v1/user/:user_id/orders

Returns orders belonging to the authenticated user.

Authentication: Yes

The path user ID must match the authenticated JWT user ID.

Otherwise:

403 Forbidden

Example:

curl \
  -H "Authorization: Bearer <JWT_TOKEN>" \
  http://localhost:8080/api/v1/user/1/orders
6.4 Cancel Order
PUT /api/v1/orders/:id/cancel

Cancels an order.

Authentication: Yes

The authenticated user must own the order.

Ownership is checked before cancellation.

Example:

curl \
  -X PUT \
  -H "Authorization: Bearer <JWT_TOKEN>" \
  http://localhost:8080/api/v1/orders/1/cancel
7. HTTP Status Codes
Status	Meaning
200 OK	Request completed successfully
201 Created	Resource created successfully
204 No Content	Resource deleted successfully
400 Bad Request	Invalid request
401 Unauthorized	Authentication is missing or invalid
403 Forbidden	Authenticated user is not authorized
404 Not Found	Resource does not exist
500 Internal Server Error	Unexpected server error
